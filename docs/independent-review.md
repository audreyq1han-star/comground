## Occurrence and measurement follow-up

Six disjoint implementation/review roles reconciled O1–O8, M1–M6 and C1–C4 before integration. The follow-up closes the local multi-date and measurement gaps rather than deferring them again. Exact-date public APIs, matching, saved/activity/reminder history, a retained-ID operator editor, optional measurement, synthetic first-touch attribution and aggregate views are now implemented.

Cross-review found and repaired two additional history defects. Unavailable saves now use the latest published snapshot for their own occurrence instead of reverting to the original saved time. Both edits and manual changed fixture imports reject removing or renaming persisted occurrence IDs before any write; dates must be cancelled instead. Regression tests cover atomic rejection and preserve existing manual replay behavior. A displayed historical choice can receive NOT_RELEVANT feedback after withdrawal; RELEVANT still requires current eligibility and publication version. Empty/repeated date queries do not silently choose another date.

A second read-only UI audit found delayed continuations that could write attribution after a persona switch, dropped focus checks while loading, and a lost acknowledgement after an unchanged focus read. Live identity epochs, continuation guards, coalesced unmeasured reads and retained presentation associations address these cases. Dedicated browser tests hold actual server responses before switching personas or refreshing, then verify the resulting state. Long source excerpts now wrap inside phone cards, and occurrence-edit evidence uses readable summary text.

The migration copies and verifies legacy private rows transactionally before clearing their old storage, keeps IDs/events/versions/outcome snapshots/reminder state, and has rollback and repeated-reopen tests. Measurement records only server-signed displayed choices, uses distinct-recipient denominators, includes empty seekers and nonresponders, and links timestamped self-reported APPLIED events to exact dates within seven days. The operator receives aggregate projections with small and complementary cohort suppression; a fictional arithmetic example is computed separately.

## Recommended next milestones

1. **Choose the pilot boundary.** One geography/coarse area, student age cohort and cause category. Define acceptable source permission, minimum safe listing fields and human safeguarding responsibility. Do not ingest students' private data from marketing channels.
2. **Connect one approved supply source.** Add a separately authorized adapter, raw-source provenance, validation/quarantine, freshness policy, failure ledger and duplicate-review workflow. Stop publication when permission or critical eligibility is unknown. Establish a human repair loop before scheduling.
3. **Validate the matching baseline.** Keep deterministic eligibility authoritative. Use the implemented consented rule-version and cohort-suppressed recommendation-to-action measures, then validate their usefulness with an approved real cohort. Test explanations with a small consenting pilot before considering an AI provider. AI must not infer eligibility or certify an organizer.
4. **Run a measured cold-start pilot.** Obtain approval for a single channel where that cohort already seeks opportunities (for example its institution's approved volunteering channel), then test message-to-useful-shortlist and completed self-report rates. Human-review factual reports. No outreach is part of this local deliverable.
5. **Prove operation before expansion.** Restore backups, exercise collection failure recovery, review freshness weekly and require sufficient permitted supply and useful matching before expanding.

## Verification limits

`tests/independent-review-e2e.mjs` adds 11 actual desktop/phone groups with explicit cross-tab reads, injected read failures and delayed save responses. It complements the full browser suite's back/forward, consent deletion, source controls and operator journeys. The first independent-run selector failures were test bugs: the expected source title omitted the fixture's synthetic suffix, then matched both initial and edited snapshots. Selectors now use the actual source title within the newest revision. The baseline Escape assertion now waits for the browser's asynchronous native close event before checking restored focus; the independent accessibility suite also verifies this behavior.

Only synthetic data is used. No deployments, pushes, merges, real feeds, scraping, outreach, account provisioning or paid resources were performed. Fixed selectable personas remain unsuitable for real student data. Local process recovery is verified; power-loss, backup restoration, penetration testing and formal accessibility certification are not.
