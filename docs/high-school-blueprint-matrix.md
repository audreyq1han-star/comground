Current implementation audit: 17 October 2026. This replaces the earlier baseline/gap table. The starting security baseline was `4edb31c4f7b6452e64df9acc446d677221ba4f59`; the evidence below refers to the current working tree, including the subsequent implementation. **Implemented locally** means a concrete synthetic capability exists. It does not mean a pilot has run, a source is permitted, a person is verified, or a launch gate has passed. Final integrated acceptance passed: **411 unit tests, 76 HTTP groups, 106 application browser groups, 7 public-preview browser groups, 6 focused accessibility groups across 23 sampled routes and 6 bounded local performance routes**. Both app builds/typechecks passed. See `docs/evidence/production-final.json`; exact clean commit is recorded in the delivery checkpoint.

The user confirmed **high school first, including students aged 18 or over; college later**. Synthetic teen 13–17 and adult high-school journeys exist. Real minor enrollment, external source activation, real student data, external sends, credentials and deployment remain disabled or outside this task. Student profiles are private; operators receive supply records, assigned minimal claim/report context and suppressed aggregates, never a student-profile directory.

## Metric reconciliation and evidence limits

The original definitions remain authoritative in `plan/metrics.csv`. Local adaptations are explicit rather than silently substituting clicks, self-reports or fixtures for confirmed outcomes.

| Original metric | Current implementation and boundary |
|---|---|
| provenance coverage / known expired matchable | Permission/evidence gates and current catalogue eligibility exclude known expired/cancelled/withdrawn records. Automated fixtures test the mechanics; 100% real provenance and zero real bad matches require a real reviewed catalogue. |
| useful match rate | Explicit relevant feedback within an inclusive seven days divided by all distinct shown-shortlist recipients, including nonresponders. Late responses separate. Save/open never implies useful. |
| next-step rate | Distinct-owner union of APPLIED and currently valid synthetic INTRODUCTION acknowledged within seven days of an exact shown occurrence; identical stored start/end dates required. Same recipient denominator; overlap displayed separately. Legacy undated APPLIED remains labeled outside the union. This is self-report or synthetic evidence, not real organizer confirmation. |
| confirmed introduction/application count | Separate synthetic evidence summary deduplicates eligible profiles. **Declared period adaptation:** fixed rolling 28 days, whereas the original calls for a 4–6-week pilot count. The actual pilot readout still uses its recorded 4–6-week window; no local rolling total is presented as that readout. |
| confirmed attendance / repeat participation | Separate synthetic evidence summary uses exact-date attendance and ended-session signup/introduction denominator, rolling 28 days; repeat uses a second distinct opportunity after a complete 28-day observation window, with partial windows separate and 90-day bounded history. Self-reported repeat history remains a different labeled measure. |
| time to first useful match | `presentation-cohorts-v2` exposes trailing-seven-day and legacy 30-day presentation cohorts side by side; median/p90 since snapshotted profile storage-consent baseline, sample/missing baseline/no-match counts. Earliest retained qualifying useful response uses up to 90 days, not an invented lifetime history; timing samples under three hidden. |
| source sync success | Trailing 14 days, on-time scheduled root/replay completion before next boundary divided by all known authorized due intervals, including missing/unfinished runs. Unknown permission history and before-activation coverage shown rather than silently counted as success. |
